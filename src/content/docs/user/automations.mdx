An automation is a short rule stored and run by the panel. It has one trigger and one or two actions. It can run without Home Assistant, though Home Assistant must be available when an action uses one of its devices. The panel's automations are separate from Home Assistant's automation editor: use Home Assistant for richer rules, conditions, or actions outside the panel's list.

**Availability:** this feature is present only in firmware builds that include Automations. If **Settings > Automations** is absent, that build does not expose the feature. The rules and panel screens are implemented and host-tested, but hardware acceptance is still in progress; follow your installation's release guidance before relying on a rule for security. Home Assistant integration 0.1.0 includes the allow-list and action path for shared entities. Version 0.2.0 adds richer device values and capability reporting; it is prepared but not released in this edition. The Z-Wave automation source is implemented and host-tested, but has not completed panel acceptance; use it only if the device appears in the editor on your build.

## Who can manage automations

Open **Settings > Automations** while all partitions are disarmed and quiet. Enter a **system master** or **installer** code when asked. Partition masters and other user codes cannot manage the list. Existing automations continue running while the panel is armed, in alarm, or being edited elsewhere, but you cannot change them until the system is disarmed and quiet.

For arming, disarming, and other less secure actions, the rule acts as the user who last saved it. The panel rechecks that user's current role and permission when the action runs. A system master can save arming and disarming actions; an installer can save device rules, but cannot save an arming or disarming action because the installer code cannot arm or disarm. Editing a rule makes the editor its new maker for those actions, so review its authority when another authorized person changes it. Ordinary device actions do not ask for a code when they run.

## Create a device automation

1. Open **Settings > Automations** and choose **Add an automation**.
2. Choose **When should it run?** and select one trigger:
   - **When the panel is armed**: choose Away, Stay, Night, or any of them. It fires after exit time ends.
   - **When the panel is disarmed**.
   - **When an alarm sounds**, or **When a fire or CO alarm sounds**.
   - **When a door or window opens**, or **When a sensor opens**: select an eligible door, window, motion, or water sensor.
   - **When a door or window closes**: select an eligible door, window, or garage-door zone. It fires after the zone has stayed closed for 10 seconds.
   - **At a time of day**: choose a time and one or more days of the week. It runs at most once on each selected day.
3. Choose one action, and optionally add a second action if the editor offers **Add an action**. Check the generated sentence and device names.
4. Set **Only between** for a time window on a non-time trigger, or **Turn it off after** for a supported on action, when those choices are useful.
5. Review any safety confirmation, then save. The list shows the trigger and actions as a sentence; automations do not have custom names.

The panel supports simple actions such as switching a light, switch, or fan on or off; toggling a light or switch; locking or unlocking a lock; opening, closing, or stopping a cover; opening or closing a water valve; turning a thermostat off; and running a scene. Available devices and actions depend on the device catalog and the permissions configured for this panel. Home Assistant 0.2.0 adds richer device values and capability reporting, so controls may vary with the integration version and what each entity supports. Z-Wave switches, dimmers, and closing a garage door are offered by the automation device source where enabled; they are not the same as native Smart Home tiles. Scripts, alarm panels, and sirens are not offered as automation actions.

An automation may have up to two actions, with at most one action per device. It is not a general rules engine: it has one trigger, no condition chains, and no branches or waits.

## Use a time trigger to arm

Choose **At a time of day**, select the days, then choose **Arm** as the only action. Select the partition and **Away**, **Stay**, or **Night**, and set the warning length from 1 to 15 minutes (5 minutes by default). The panel gives a steady Home card and status-bar notice and sounds the chime once a minute while the warning runs.

At the warning, check Home and the zone list. If the partition is not ready and **Bypass open zones** is off, the panel does not arm and reports the open zone. If enabled, the automation can bypass eligible open burglary zones and arm. A sensor in trouble still prevents arming; fire, CO, and 24-hour zones are never bypassed. Bypassed zones are watched again after they close and each bypass ends at the next disarm.

The installer controls **Allow less secure automations** at **Settings > About > Installer > Delays and arming > Arming**. If it is off, the arming editor does not offer **Bypass open zones**. If it is on, the rule's bypass choice is still off by default; turn it on only if leaving an open zone out of protection is acceptable.

<PanelShot src="/images/panel/automation-warning.png" alt="Home screen showing an automatic arming warning and Put off button" caption="The warning stays visible and gives you time to delay the automatic arming." />

Choose **Put off** to postpone an arming warning. Select **An hour later** or **Not tonight** (shown as **Not today** for a daytime arm), then enter a code. Any valid user code can put an arming off for an hour; **Not tonight/Not today** requires a code that can disarm that partition. A wrong code counts toward keypad lockout. The warning returns five minutes before an hourly delay expires. Home shows who put it off and when the rule will try again.

This time-triggered automation is the panel's current auto-arm method. The separate weekly schedule feature for exception dates, scheduled users, and independent auto-disarm is not available yet. Auto-arm does not run when the clock is unset, and a missed time is not replayed later.

## Understand safety confirmations and permissions

The installer can turn off less secure automations. This setting covers disarming, unlocking, opening, and stopping. When it is off, the editor will not offer those actions; a saved automation containing one is kept but cannot run until the installer allows it again.

When you select a scene or a switch-on/toggle action, the editor asks for a one-time confirmation because the action may have effects beyond what the panel can inspect. The scene confirmation warns that the panel cannot see what the scene does; a Home Assistant scene may affect entities that are not individually shared for panel control, including unlocking or opening something, without a separate code prompt or the installer setting for direct less secure actions. Use a scene only if you trust its complete contents. A switch-on/toggle confirmation warns against using a switch that operates a door, gate, or garage.

For a door, window, motion, or alarm trigger, the editor also asks you to confirm in plain language before saving a less secure action, such as “Anyone who opens Front Door will unlock Front Door Lock.” It asks again if you later change the trigger or action. An armed trigger also needs confirmation before an unlock, open, or stop. A disarm after an alarm or fire trigger is refused, and a rule cannot disarm the same partition that its own trigger just armed. The editor does not ask for a keypad code for these save confirmations.

At runtime, a device action is rechecked against the saved-by user's permission and the installer setting. The panel never lets an automation silence a sounding alarm, issue Panic, or bypass zones as a separate action. Arming is only from Disarmed; it does not change an already armed partition to another level.

## Edit, pause, test, or delete a rule

1. Open **Settings > Automations** and select a rule.
2. Use the **Use this automation** switch to enable or disable it. A disabled rule stays in the list but does not run.
3. Select its trigger or action rows to change them. Review and save the updated rule; safety confirmations may appear again.
4. Choose **Try it now** to run the device actions once. This does not run the trigger or execute an arming action.
5. Choose **Delete** and confirm when the rule is no longer needed.

The panel stores up to 16 automations. The list shows when a rule last ran and its most recent result, such as **Didn't work** or **Can't run**. That result is kept until the panel restarts. Open a rule to read the reason; common causes include an offline or missing device, an action the device refused, the installer setting blocking the action, an unset clock for a time rule, or a partition that was not ready to arm.

## Examples

- **Porch light at the door:** when the front door opens, turn on the porch light. Use **Only between** to limit it to evening and overnight hours.
- **Lock after leaving:** when the panel is armed Away, lock the selected lock. Check the rule's generated sentence and the lock's actual state after saving it.
- **Night arming:** at 10:30 PM every day, arm Night after a five-minute warning. Leave **Bypass open zones** off unless the installer has enabled the option and you have decided that behavior is appropriate.
- **Water response:** when the water sensor opens, close the water valve. The panel can run the rule locally, but the Home Assistant device must be online to receive the command.

## Troubleshoot a rule

- **No Automations page:** the current firmware may not include it. Check the build and firmware notes.
- **Can't edit:** disarm all partitions and clear any active alarm state. Then reopen Settings with a system master or installer code.
- **A time rule waits:** set the panel clock and time zone in **Settings > Time and language**. It does not catch up for a missed time.
- **A rule is shown as Can't run:** open it and follow the explanation. A rule from newer software cannot run or be edited by this build; it can only be deleted.
- **A device action failed:** confirm the device is online in its source and still shared for control. Check its state before retrying an unlock, opening, or stop action.
- **Automatic arming did not happen:** review the last result, the warning on Home, open zones, and the partition's status. If a restart interrupts the warning, that day's arming is skipped rather than performed without its full warning.
- **A rule ran but did not produce the expected result:** the panel sends each action only once. Check the device itself and the last-run result before changing or retrying the rule.
