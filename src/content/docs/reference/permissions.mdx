Each code has a level. The level and the partitions of the code decide what the person can do. Use this page to see what each level can do on the panel and in Panel Manager.

## Code levels

| Level | Who has it | What it can do |
| --- | --- | --- |
| **Standard** | Each person in the household | Arms, disarms, bypasses and changes the chime in its partitions. A new user gets this level. |
| **Arm only** | For example, a cleaner who locks up | Arms only. It cannot disarm or bypass. |
| **Guest** | A visitor | Arms, and disarms only what the same code armed. It cannot bypass. |
| **Duress** | A person who can be forced to disarm | Disarms like a standard code and records a private event. A connected service can report it. |
| **Partition master** | The person who manages one area | Everything a standard code can do. It also manages the users of its own partitions. |
| **System master** | The person who manages the household | Everything, in all partitions. It manages all users except the installer. |
| **Installer** | The installer | Programs the panel and manages all users. It never arms or disarms. |

The installer code and the system master code work in all partitions. Other codes work only in the partitions that the person who manages users chose. See [Users and codes](/user/users-codes/).

<Aside type="note">
The installer code does not arm, disarm or restart the exit time. In installer mode, nobody can arm the panel. The installer uses a household code to test arming.
</Aside>

Anyone can see the zones, **Activity** without private events, the troubles and the state of the SD card. The chime needs no code when the installer turns off **Chime needs a code**.

### Notes on users and codes

- A partition master manages only users whose partitions are all inside its own partitions. It can give only the levels **Standard**, **Arm only**, **Guest** and **Duress**.
- Only the system master and the installer can make a partition master.
- Nobody can change their own level. Nobody can delete the installer or the system master.
- The installer can change the installer code and the master code without the old code, in **Installer and master codes**.

### Notes on Smart Home

- A protected device asks for a system master, partition master or installer code before each change. After a correct code, more changes on the same panel go through for 90 seconds.
- A lock asks for a code each time it unlocks. A garage door, cover or valve asks for a code each time it opens. This code must be able to disarm.
- From the factory, no device is protected. See [Protect a device with a master code](/user/smart-home/#protect-a-device-with-a-master-code).

### Notes on automations

An automation acts as the person who saved it last. When it runs, the panel checks the level of that person again. The installer can save device actions, but not arming or disarming actions. The installer decides with **Allow less secure automations** if automations can disarm, unlock and open. See [Create panel automations](/user/automations/#safety-and-permissions).

## In Panel Manager

Panel Manager uses a browser account with a password, not a code. The account has the same level and partitions as the user. A browser account never gets more authority than the code level of that person.

| Task | Standard | Partition master | System master | Installer |
| --- | --- | --- | --- | --- |
| See the status, zones, troubles and **Activity** | Own partitions | Own partitions | Yes | Yes |
| Use the remote keypad | Yes | Yes | Yes | Yes |
| Arm, disarm and bypass | As with the code | As with the code | As with the code | Bypass only |
| Change the display and sound settings | Yes | Yes | Yes | Yes |
| Change your own browser password | Yes | Yes | Yes | Yes |
| Manage people, codes and browser sign-ins | No | Lower users in own partitions | All except the installer | All |
| Change the network, the time, the language and the region | No | Yes | Yes | Yes |
| Start a walk test | No | Yes | Yes | Yes |
| Change integrations and automations | No | No | Yes | Yes |
| Check for and install a software update | No | No | Yes | Yes |
| Manage the SD card | No | No | Yes | Yes |
| Program zones, sensors, partitions, keypads and alarm rules | No | No | No | Yes |
| Change the update server or channel, allow panic alarms over MQTT | No | No | No | Yes |
| Turn on developer tools, install a signed development file, factory reset | No | No | No | Yes |

**Arm only**, **Guest** and **Duress** codes cannot have a browser sign-in. The remote keypad works like the touchscreen, so the panel still asks for a code where it needs one. See [Browser accounts](/panel-manager/accounts/).

## Keypad codes and browser passwords

A keypad code works only on the panel. It does not sign in to Panel Manager. A browser password has 12 to 64 characters.

- The installer turns on its own sign-in at **Settings > About > Installer > Browser sign-in**.
- For another user, the person who manages that user opens **Settings > Users >** the name **> Browser sign-in**.
- A password that you set for another person is temporary. That person chooses a new password at the first sign-in.

## When the panel is armed

While a partition is armed or an alarm sounds, nobody can change settings, on the panel or in Panel Manager. **Settings** opens again when all partitions are disarmed and the alarm is silenced. In Panel Manager, the remote keypad, your own password and **Sign out** still work.

A code that opens a protected section of **Settings** stays valid while **Settings** is open. It ends when you close **Settings** or after a time without a touch.
