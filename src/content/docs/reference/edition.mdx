Published integration 0.1.0 already supports explicitly selected binary-sensor zone inputs and a separate device-control allow-list. The prepared 0.2.0 candidate adds richer device values/capabilities and exports supported panel Z-Wave outputs to Home Assistant. **A screenshot displaying 0.2.0 does not mean that release has been published.** Use compatible panel and integration releases and check their release notes.

The Smart Home and automation pages describe the reviewed implementation. Availability depends on the installed build and selected device capabilities. Software and simulator checks do not establish hardware or installation acceptance.

## Find your software version

On the panel, open **Settings > About** to reach **About this panel**. In Home Assistant, open the **RoboAlarms** integration details. In the Flasher, review the selected release and board before starting a job.

The manuals are deliberate snapshots, refreshed when the owner requests an edition. Labels and options can differ on older or newer software.

## What is covered

The User Guide covers daily alarm operation, partitions, users, Smart Home, panel automations, screen and sound, time/language, updates and SD-card tasks. The Installer Guide covers software setup, commissioning and radio/zone configuration. Integrations has detailed Home Assistant setup, sharing, usage and recovery, with links to MQTT and phone notifications. Flasher and Panel Manager have separate task guides.

Physical mounting, wiring design and purchasing remain outside the manual; use [RoboAlarms hardware](https://roboalarms.com/hardware/) and vendor instructions. PDF production, the separate Settings > Devices rename/hide page, and unfinished hardware acceptance are outside this edition. The same operating instructions apply across supported sizes; every panel image uses the 7-inch layout.

## Screenshot sources

### Panel

Panel screenshots use the actual UI and alarm engine in the host preview, rendered at **1024 × 600** for the 7-inch panel, with fictional data. Each screenshot scenario changes both factory codes through the engine after initialization; every normal capture asserts that no factory code remains. It omits engineering scenes that test factory-code refusal without altering production defaults or warning logic.

Crops retain the controls and context taught by the caption. Warnings remain when they are the task's subject. No UI pixels are repainted. The images are software illustrations, not photographs or proof that physical sensors work.
Release numbers and dates shown in the preview are examples; check the version and offer on your own panel.

### Home Assistant

Home Assistant images were recaptured on **13 October 2026** in an isolated Docker lab. They show its real 2026.10.1 interface and the unmodified 0.2.0 candidate. The fictional panel supplies pairing and zone/status data; the lab does not test durable trust, firmware persistence or complete device control.

The pairing illustrations on both screens match. Naming, sharing selections and the alarm-code prompt show the actual interface. No real alarm command was sent for that prompt. HACS instructions follow official documentation; its GitHub authorization was not captured using an owner's account.

Some integration dialogs still say **Devices**. The operating screen on the reviewed panel is named **Smart Home**.

### Desktop Flasher

Flasher images come from the owner's original **Windows desktop app** screenshots on the project website. Their original capture dates are unknown. Whole images are retained where useful; the progress detail is cropped to the relevant status, excluding the chip identity. The website originals are unchanged. They show an older five-step development interface; the current guide describes the eight-step **Plan → Wire → Install** flow. Image versions are examples, not release recommendations.

Fresh desktop capture was attempted, but the Windows capture service could not access the display. Browser images were not substituted. Captions and the provenance manifest identify every retained image.

### Panel Manager

Panel Manager images show the current production browser frontend over a fictional backend. Its remote keypad receives a genuine 7-inch host-rendered panel frame, with the real remote-session banner, through the still-frame transport. This illustrates the interface without testing live hardware, remote input or video performance.

Image manifests record source files, dimensions, crop rectangles, dates and hashes. Example names, addresses, pairing digits and credentials are not installation values to copy.

## Before relying on a new setup

Follow the [commissioning checklist](/installer/commissioning/). Verify sensor states, alarm operation, access permissions, device actions and notification delivery. Record unperformed checks as untested.

Home Assistant, MQTT and phone notifications remain optional. Their connection does not establish professional monitoring or guaranteed emergency dispatch. Visit [RoboAlarms](https://roboalarms.com) for project information and releases.
