Use this page when Home Assistant cannot find, pair or stay connected to the panel. First find out when the problem starts: when Home Assistant looks for the panel, during the pairing, or after a working connection.

## Common problems

| Problem | Do this |
| --- | --- |
| Home Assistant does not find the panel. | On the panel, turn on **Home Assistant** under **Settings > Integrations**. Discovery works only on the same subnet. On another subnet, add the panel with its IP address. |
| **Could not reach the panel** | Check the panel's IP address under **Settings > Wi-Fi and network**. Check that **Home Assistant** is on and that the network allows TCP port 6054 from Home Assistant to the panel. |
| **The panel isn't pairing right now** | On the panel, push **Pair with Home Assistant** and enter the system master code or the installer code. Continue in Home Assistant within two minutes. |
| **Pairing timed out on the panel** | Open pairing on the panel again, and continue faster. |
| **The panel rejected the pairing** | Someone pushed **No, reject**, or the codes were not the same. Pair again and compare the codes. |
| **The pairing could not be trusted and was stopped** | Check that you connect to the correct panel on a network that you trust. Then pair again. |
| **This panel is already configured** | The panel is already in Home Assistant. Home Assistant updated its address. Use the existing entry. |
| Home Assistant asks to pair again, or shows **The certificate has changed**. | This happens after a factory reset or an unpair. Check that it is your panel. Follow the reauthentication prompt and compare a new code. |
| **That address now belongs to a different panel** | Stop. Find out which panel uses that address before you change anything. |
| The entities show as unavailable. | Check the panel's power and Wi-Fi, and the state under **Settings > Integrations > Home Assistant**. The integration connects again by itself. |
| **Panel protocol is incompatible** | Update the integration and the panel software to versions that work together. The connection comes back by itself. |
| A shared sensor is not in **Pick the sensor**. | Check that the sensor is in **Entities the panel may use as zones** and is available in Home Assistant. |
| The panel refuses an action. | Read the message in Home Assistant. The code, the user's permission, an open zone or a panel rule can stop it. |

## Change the panel address

If the panel gets a new IP address, change the address in Home Assistant. The pairing, the entities and the sharing lists stay.

<Steps>

1. In Home Assistant, open **Settings > Devices & services > RoboAlarms**.
2. Open the menu of the panel entry, and then click **Reconfigure**.
3. Type the new IP address in **Host**. Keep **Port** at `6054`.
4. Click **Submit**.

   Home Assistant shows **The panel address has been updated**.

</Steps>

Home Assistant checks the panel's identity before it saves the address. If a different panel answers, Home Assistant shows **That address now belongs to a different panel**.

## Unpair or move Home Assistant

<Steps>

1. On the panel, push **Settings > Integrations > Home Assistant**.
2. Enter the system master code or the installer code.
3. Push and hold **Unpair**.

   The panel removes Home Assistant's access until it pairs again.

</Steps>

To pair the same or another Home Assistant server, push **Pair with Home Assistant** and compare a new code.

If you delete the RoboAlarms entry in Home Assistant, the panel still trusts that server. Use **Unpair** on the panel to remove the access. If you turn off the **Home Assistant** switch, the panel stops the connection and the discovery, but it keeps the pairing.

## Update the integration

<Steps>

1. Update **RoboAlarms** in HACS. For a manual installation, replace the `custom_components/roboalarms` folder with the new version.
2. Restart Home Assistant.
3. Check the release notes on the [releases page](https://github.com/RoboAlarms/ha-addon/releases) for the panel software that the integration needs.

</Steps>

Do not delete and add the integration again to solve a version problem. Install matching versions, and the connection comes back by itself. For panel software updates, see [Software updates and SD card](/user/updates-storage/).

## Report a problem

Report a problem in the [integration issue tracker](https://github.com/RoboAlarms/ha-addon/issues). Give the Home Assistant version, the integration version, the panel software version and the message that you saw. Tell when the problem starts: when Home Assistant looks for the panel, during the pairing, or later.

<Aside type="caution" title="Caution">
Do not put alarm codes, pairing codes, certificates, private addresses or network names in a report. Other people can read the report.
</Aside>
