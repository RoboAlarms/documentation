After the pairing, Home Assistant has entities for the panel's partitions, zones, health and events. Use this page to find the entities, arm and disarm from Home Assistant and use the panel in automations.

<Aside type="note" title="Before you start">
- The panel is paired with Home Assistant. See [Install and pair Home Assistant](/integrations/home-assistant-setup/).
- To arm or disarm, you need a panel user code that has permission for the partition.
- Test each action while the panel is disarmed and somebody watches it.
</Aside>

## Entities in Home Assistant

| Entity | What it shows or does |
| --- | --- |
| Alarm control panel | One for each partition, with **Home**, **Away**, **Night** and **Disarmed**. **Home** is the panel's Stay mode. |
| Zone binary sensor | One for each zone. Each zone is a device under the panel. |
| **Tamper**, **Low battery**, **Supervision** | Diagnostic entities of each zone. |
| **Trouble**, **AC power**, **Installer mode**, **Uptime**, **Wi-Fi signal** | The health of the panel. |
| **Chime** | A switch for each partition that turns the chime on or off. |
| **Restart exit delay** | A button for each partition that starts the exit time again. |
| **Event** | The latest panel event, with its details as attributes. |
| **Firmware** | Shows a new panel software version and the progress of an installation. You allow and start the installation on the panel. |
| Panel Z-Wave devices | The panel's own Z-Wave switches, dimmers and garage doors. A garage door closes from Home Assistant, but opens only at the panel. |

The entity IDs depend on the panel's name, the partition numbers and the Home Assistant entity registry. To find them, open **Settings > Devices & services > RoboAlarms** and the panel device. If the connection stops, the entities show as unavailable until the connection is back.

## Arm and disarm from Home Assistant

<Steps>

1. Open the alarm entity of the partition, on the panel device or on a dashboard card.
2. Click **Home**, **Away** or **Night** to arm. Click **Disarmed** to disarm.
3. Type your panel user code, and then confirm.
4. Check the state in Home Assistant and on the panel.

</Steps>

The panel checks the code and its permissions, as at the keypad. Home Assistant does not keep the code. If the panel refuses the request, Home Assistant shows the reason:

| Message | Meaning |
| --- | --- |
| **The panel did not accept that code** | The code is wrong. |
| **That code is not allowed to do this on the panel** | The user has no permission for this action or partition. |
| **The panel needs a user code for this** | Type a code. |
| **The panel is not taking codes for now after too many wrong ones** | The keypad lockout is on. Wait a few minutes. |

## Send a phone message on an alarm

This example sends a message to the Home Assistant Companion app when the panel reports an alarm. It leaves out silent alarms. Choose your own event entity and notification action in the Home Assistant editor.

```yaml
alias: "Notify on a RoboAlarms alarm"
triggers:
  - trigger: state
    entity_id: event.home_event
conditions:
  - condition: template
    value_template: >-
      {{ trigger.to_state is not none
         and trigger.to_state.attributes.get('event_type') == 'alarm'
         and not trigger.to_state.attributes.get('silent', false) }}
actions:
  - action: notify.mobile_app_example_phone
    data:
      title: "Alarm"
      message: >-
        {{ trigger.to_state.attributes.get('zone_name') or
           'A RoboAlarms partition reported an alarm.' }}
```

The state of the event entity is the time of the latest event. The `event_type` attribute holds the kind of event. Other attributes can include `partition`, `zone`, `zone_name`, `cause`, `source` and `silent`. The trigger has no `to` value, so it reacts to each new event.

<Aside type="caution" title="Caution">
Decide with the owner before an automation reacts to a silent alarm or a duress code. A message on a phone can show a silent alarm to the wrong person.
</Aside>

## Arm from an automation

This example arms Away when everyone leaves and the front door is closed. Change every entity ID and the example code.

```yaml
alias: "Arm RoboAlarms away when everyone leaves"
triggers:
  - trigger: state
    entity_id: group.household
    from: "home"
    to: "not_home"
conditions:
  - condition: state
    entity_id: binary_sensor.front_door
    state: "off"
actions:
  - action: alarm_control_panel.alarm_arm_away
    target:
      entity_id: alarm_control_panel.home_partition_1
    data:
      code: "246810"
```

Do not put a real code in a shared dashboard, in public YAML or in an automation that other people can edit. The panel can refuse the command, for example for a wrong code or an open zone. Home Assistant cannot go around the panel's rules.

## Panel actions

**Developer Tools > Actions** has these RoboAlarms actions. Each one needs the panel entry and a user code.

| Action | What it does |
| --- | --- |
| `roboalarms.arm` | Arms a partition at `stay`, `away` or `night`. It can also arm with **Silent exit** or **No entry delay**. |
| `roboalarms.bypass_zone` | Bypasses one zone. |
| `roboalarms.unbypass_zone` | Ends the bypass of one zone. |
| `roboalarms.panic` | Asks for a police, fire or medical panic alarm. The panel refuses it unless the panel allows remote panic. |

Use the alarm entity for ordinary arming and disarming. Use a bypass only for an agreed reason, and end it afterwards.

<Aside type="danger" title="Warning">
Do not bypass a fire, CO or other life-safety zone from an automation. A bypassed zone does not cause an alarm.
</Aside>

<Aside type="tip" title="Check the result">
The alarm entity shows the same state as the panel. A test event, for example an arm, shows in the **Event** entity.
</Aside>
